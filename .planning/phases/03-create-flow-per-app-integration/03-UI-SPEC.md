## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps between icon/text, compact chip spacing |
| sm | 8px | Grid/card internal padding, field label-to-input gap |
| md | 16px | Default control spacing, section padding, modal edge padding |
| lg | 24px | Group spacing between form sections |
| xl | 32px | Major panel inset / breathing room in detail-create area |
| 2xl | 48px | Large section separation in long forms |
| 3xl | 64px | Reserved for future full-screen empty states only |

Exceptions: Minimum touch target for icon-only buttons is **44px** (plus button, back/cancel affordances).

## Interaction Contracts (Phase 3 Scope)

### 1) Type Picker Grid

- Layout is a **2×4 grid** rendered in the create slot (right panel on wide, pushed route on narrow). 
- Must show all 7 `WikiPageType` values; slot 8 remains an inert spacer (no tap target).
- Each card contains:
  - top icon (24px)
  - type display name (`WikiPageTypeExtension.displayName`)
  - full-card tap target (min 44px height)
- Card states:
  - Rest: secondary surface + outlineVariant border
  - Hover/press: surfaceContainerHigh
  - Selected: 2px primary border + primary icon/text tint
- Recommended icon mapping (aligned with existing list icons):
  - creature `Icons.pets`
  - spell `Icons.auto_awesome`
  - item `Icons.gavel`
  - rule `Icons.menu_book`
  - location `Icons.location_on`
  - npc `Icons.person`
  - other `Icons.article`
- Cancellation affordance is required (Back in app bar or Cancel text button).

### 2) Dynamic Per-Type Create Form

- Form structure:
  1. Shared fields (all types): title, body (markdown), tags, aliases
  2. Type-specific structured fields from `WikiPageTypeExtension.fields`
- Render contract for field definitions:
  - `text` -> single-line `TextFormField`
  - `number` -> numeric `TextFormField` with number keyboard
  - `multiline` -> min 3-line `TextFormField`
  - `select` (if schema uses it) -> `DropdownButtonFormField`
- Validation:
  - Title is required and trimmed (non-empty)
  - Type-specific required fields (if marked required in schema) must block submit
- Submission output contract:
  - `title/body/tags/aliases` map directly to `WikiPage`
  - type-specific values map to `WikiPage.statBlock[key]`
  - `pageType` equals selected picker type

### 3) Two-Panel vs Single-Panel Create Navigation Behavior

- **Two-panel (>=600dp):** Create flow replaces right detail panel in-place.
  - Left list panel remains visible and interactive.
  - Cancel returns right panel to previously selected page detail (or default empty prompt).
  - Save exits create mode and shows new page detail in right panel.
- **Single-panel (<600dp):** Create flow is pushed via `Navigator` from list panel.
  - Cancel pops route and returns to list panel.
  - Save pops/create route and opens detail view for newly created page.
- In both modes, successful save must auto-select the new page in provider state.

### 4) Plus-Button Entry Point in Modal

- Add `IconButton(Icons.add)` in `WikiModalShell` AppBar actions.
- Tooltip: `Create page`.
- Behavior on tap:
  1. Enter create mode (`isCreating = true`)
  2. Show type picker first (no preselected type)
  3. Block duplicate submissions while save in flight
- Accessibility:
  - semantic label `Create wiki page`
  - 44px minimum hit area

### 5) Book Icon AppBar Triggers in Both Apps

- `apps/dm_app/lib/main.dart`: existing `Icons.menu_book` action must call `WikiModalShell.show(...)`.
- `apps/companion_app/lib/main.dart`: add matching AppBar action path (or pass actions into `GenericTabView`) to open same modal.
- Consistency contract:
  - Icon: `Icons.menu_book`
  - Tooltip: `Wiki`
  - Interaction: single tap opens full-screen wiki modal
  - Modal entry context is app-local but uses shared core wiki UI components

## State & Feedback Contract

- On successful create:
  1. persist via `WikiStorageService`
  2. append to provider pages list
  3. refresh list immediately
  4. select new page
  5. transition to detail view
- On validation failure: inline field errors + keep user on form
- On persistence failure: show non-blocking error banner/snackbar with retry path
