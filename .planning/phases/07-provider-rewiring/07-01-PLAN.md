  <action>Create a new StatefulWidget called GameModelFormBuilder that renders form inputs from a List&lt;FieldSchema&gt;.

Key requirements:
1. Constructor takes: `required List&lt;FieldSchema&gt; fields`, `required FormFieldValidator&lt;String&gt;? validator` (optional, applied to required fields), `Map&lt;String, TextEditingController&gt; controllers` (map of field key → controller)
2. In createState, initialize TextEditingControllers for each field that doesn't already have one provided (caller manages controllers for state persistence)
3. In build, return a Column of form widgets — one per FieldSchema
4. Switch on `field.inputType`:
   - `FieldInputType.text` → TextFormField with labelText=field.label, hintText=field.hint
   - `FieldInputType.number` → TextFormField with keyboardType=TextInputType.number, labelText=field.label
   - `FieldInputType.multiline` → TextFormField with minLines=3, maxLines=5, labelText=field.label
   - `FieldInputType.select` → DropdownButtonFormField with items from `field.enumOptions` (NOT field.options — the JSON uses enumOptions). Use field.enumOptions ?? []. Each item's value and display text is the option string.
   - For checkbox, list, dice: render a disabled TextFormField with label "TODO: {inputType.name} input" — these exist in the enum but aren't used by D&D 5e wiki types yet
5. Validator: if `field.required` is true, add validator that returns '${field.label} is required' when value is null/empty
6. For number fields, also validate that the value parses as a number: '${field.label} must be a number'
7. Dispose all controllers created internally in dispose()
8. Do NOT import WikiPageType, WikiFieldInputType, or WikiPageFieldDefinition — this widget is purely GameModel-driven

    required this.controllers,
  });
  final List&lt;FieldSchema&gt; fields;

  // ...
}
